## 处理流程

1. 保留原始目标、对象、版本、时间及需要交付的结果，复用已有上下文，避免重复追问。
2. 查内部知识并读必要全文，区分内部无匹配、资料部分覆盖、来源冲突、后端不可用。
3. 检索相关也要核对要求覆盖；即使 pass，缺关键资料时仍进入补证。
4. 缺关键用户信息时只问影响下一步的内容；缺可查事实时查公开一手资料；
   需要实际环境证明时，在已授权范围内检查本地环境或做最小实验。
5. 核对新增来源的对象、版本、时间与原文支持，区分搜索摘要、已读全文和实际执行观察。
6. 证据足够时回答；部分支持时给有据部分并说明缺口；冲突未解、工具不可用、
   无可靠来源或预算耗尽时说明查证经过与停止原因，不停在笼统的“知识库没有”。
7. 临时外部证据可以服务本次回答，有复用价值时再提交待审知识，不自动生效。

内部改写和外部补证分开计数，但共享本次任务预算。没有新信息时停止同类重复搜索。
本期预算随评测明确记录，不将测试配置当作所有任务的固定最优值。
私有报销入口无法从公开网页确定时，不编造也不外发内部资料；缺具体产品身份不能随意搜索一个同名 API。
外查工具缺失时明确说明能力缺口，不能伪造“已联网”。

## 场景与验收

| 场景 | 应有表现 |
|---|---|
| 内部证据已经充分 | 直接给有据答案；不机械地为每个问题外查 |
| 内部相关但缺可公开查证的 URL/版本参数 | 当前宿主实际外查、打开来源核对，再回答；引用可追溯 |
| 缺具体组织/产品等决定性对象 | 先澄清关键对象，不能搜索一个不相干系统后代答 |
| 内外来源冲突或版本不符 | 继续核验范围或报告未解决冲突，不能默认“最新”覆盖所有旧环境 |
| 外查无结果、失败或未提供工具 | 说明已尝试内容、缺什么、为何停止，不伪装查证成功 |
| 需要环境验证的方法问题 | 区分给操作方法和实际执行；未执行不能报设备/模型已验证 |

自动结构检查只证明记录完整、引用和观察关联有效，不证明原文语义充分或网页内容真实。
真实当前宿主走查与固定回放分别标明；不能用脚本填入的预设决定证明模型自主选择了正确行动。
线上外部资料可能变化，使用保存的来源定位、时间与必要摘录核对；测试不依赖实时网页永远不变。
