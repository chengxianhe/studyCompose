## 结论

底座选型与已批准的分期方向一致：SQLite 真源、可重建 ES、离线本地检索模型、
可追溯关系与 MCP 仍在服务完整目标。当前交付主要是治理、检索和关系查询底座，
理解、长期记忆、发散、自更新和自进步尚未成为可验证的系统能力。

已出现的偏差集中在运行接线、质量验收与正式流程；若继续仅按接口和测试数量推进，
容易形成“模块越来越多、对 Agent 的实际收益仍未证明”的建设失衡。
本轮修复一处实际深度预算 bug，并去除核心对页面模块的反向依赖；其余未完成方向不作为 T-028 的缺陷强行扩围。

## 原始检索流程逐项核对

| 环节 | 实际证据 | 判断 |
|---|---|---|
| 解析、结构分块、父子关联 | `ingest/chunker.py`；现有知识 Markdown/纯文本，关联父知识 ID | 符合已批准范围；PDF/OCR 等暂缓 |
| BM25 + 向量双索引 | `ingest/es_index.py`，固定模型缓存/摘要 | 主干已有实现；双索引均为派生数据 |
| 可选生成问题/摘要 | 无对应实现 | 原图可选项，未做，不属于隐藏删减 |
| BM25 ∥ kNN → RRF | `search/es_retriever.py`；分别前 40，应用层融合取 30 | 应用层 RRF 是已确认的 Basic 许可适配 |
| Cross-Encoder 重排 | `search/rerank.py`；前 20 块本地重排 | 已实现；阈值 0.5 尚缺代表性样本校准 |
| Relevance Grader | `has_relevant_evidence` 仅检查最高重排分是否过阈 | 是相关性闸门，不是充分性/真实性/冲突裁决器 |
| 改写重检索 ≤2轮 | `attempt=0..2`，返回 retry/insufficient；查询由宿主改写 | 已批准的宿主分工；固定句协议测试不证明自主改写有效 |
| 注入 LLM 生成 | 返回片段/父 ID/来源，由当前会话生成 | 平台没有独立生成闭环，也没有答案级引用覆盖验收 |
| 当前运行使用上述链路 | 本轮实际搜索为 `sqlite_fallback`、`grade=unavailable` | 当前会话不能称完整 ES 链路已运行；隔离集成与实际运行分开 |

`pass` 目前只表示至少一个候选达到相关阈值，不表示证据已经足够回答全部问题，
也不表示知识彼此无冲突。先建立质量样本，不能未经评测就修改阈值或宣称提高正确率。

## 完整能力覆盖

| 能力 | 当前交付程度 | 仍待建设 |
|---|---|---|
| C01 接入治理 | 提案、审核、时效、分块、来源版本元数据 | 更多来源接入、修订历史与自动同步 |
| C02 语义意图 | 契约表达显式目标，主要依赖宿主模型理解 | 通用意图结构、歧义/指代、概念对齐与质量验证 |
| C03 分层记忆 | 文件接续和知识库提供部分持久记忆 | 偏好/经历/方法分层、纠正/遗忘、空间隔离 |
| C04 检索上下文 | 本地混合检索、重排、来源片段 | 实际运行、上下文装配、改写/回答质量与预算 |
| C05 图谱关联 | 来源/依赖/替代、有界追溯与人工审核 | 概念同义/支持/冲突/类比；尚未接入检索增强 |
| C06 发散比较 | 当前模型在会话中可以提出方案 | 可复用探索流程、反例与方案收益评测 |
| C07 自检复检 | 服务/模型 doctor、时效和影响路径 | 来源监测、复检调度、语义过期与质量漂移 |
| C08 学习改进 | 经验提案、人工审核、代码验证证据 | 固定质量集、保留集、实验、发布/回退和外部方法同步 |
| C09 通用接入 | 本机 MCP、备份、审计与模块化服务 | 跨宿主/领域实际验收、认证隔离、恢复和成本观测 |

API 与报销流程的夹具证明同一结构可表示两类资料，不证明跨语言语义能力或跨领域任务表现。
图谱当前不参与 `knowledge.search`，所以还不能声称已经提升检索或关联理解效果。
这符合 T-028 不改排序的约定；增强检索必须作为后续有评测对照的显式任务。

## 建议的接续顺序

1. 收口当前 T-028 修复与自动检查，人工审查状态不变。
2. 完成运行接线，分别检查真实服务与当前宿主可见性，执行一个有来源的真实检索/追溯任务。
3. 建立小型代表性质量基线：中文/英文、技术/非代码、更新/冲突/无答案、用户更正。
   同时记录效果、耗时和 token；实施前单独确认案例与指标，避免为评测搭大框架。
4. 再在明确任务中验证“检索 + 图谱解释 + 上下文”的收益；与只检索基线比较。
5. 根据实际失败案例确定概念层、记忆和主动复检的先后，完整长期目标继续保留。

这是优先级建议，没有自动扩大 T-028 契约、启动服务或批准下一轮设计。
